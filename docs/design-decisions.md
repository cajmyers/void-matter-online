# Void Matter Online: design decisions

Status: design discussion only. No implementation has started.
Latest additions: section 13 (map, tiles and connectivity), section 14 (rulings from the technical review) and **section 15 (rulings from the second review: terms, combat model, loot, decks, saves, soft-locks, attack pipeline)**, which carry **stable ruling IDs** (for example `MAP-3`, `CMB-3`) so tests and code can cite them. Older rulings in sections 1 to 12 are not numbered yet. Where section 13, 14 or 15 conflicts with an older section, **13, 14 and 15 win** (later sections beat earlier ones) and the older text has been edited to point there.

Content tables (sector deck assignment, copies per card, enemy deck counts, the first slice) live in `content-data.md`. Terms: **globalRound**, **combatRound** and **turn** are defined in `TRM-1` and used everywhere below; a bare "round" in older text means globalRound unless it says "combat round".
Source rules: **Void Matter Rulebook V5** (PDF provided by the owner).
Reference simulator: `card-sheet-tool` (read-only; see the project rule).

This document records decisions made in conversation, with the reasoning and the risks that were raised. Where it conflicts with `combat-reference.md`, **this document wins**. That file describes the simulator, and the simulator differs from V5 in places (see "Rulebook vs simulator").

## 1. Product

| Decision | Detail |
|---|---|
| Shape | Solo play against bot rivals. Not human multiplayer. |
| Bot count | Configurable, 1 to 3 (2 to 4 player boards). |
| Devices | Desktop browsers only. |

### Known risks accepted
- A full set of 1 to 3 bots with real behaviour is likely the most expensive part of the project and the one with the least gameplay payoff per unit of effort.
- The common-technologies slice does not stress the effect language (see section 5).

## 2. Bot rivals

| Topic | Decision |
|---|---|
| Actions | Move, trade, upgrade, explore, take and redeem missions. |
| Presence | Physical ships on the map, under the real rules. |
| Blocking | Accepted. A bot ship in a shared sector blocks **Interact, Repair and Move** for the ships there (a mutual pin, see "Movement and Evade"), but **never blocks Trade**. |
| Winning | **The bot can win** by taking its third VM (the game ends immediately, no ties). Redeeming a mission gives 1 VM, so the bot races you. |
| Starting fights | **The bot can initiate combat whenever its logic chooses** (revised: the earlier "never starts fights" rule was dropped when blockading the Nexus became designed counterplay). Reasons to attack are narrow: Spoils of War, dislodging a blockader, or destroying a ship. VM cannot be stolen. |
| Difficulty | **No difficulty setting in v1.** One tuned level. No target win rate or game length has been chosen yet ("see how it pans out"). Risk: without a target, a tuning change can't be judged as better or worse. Mitigation: have each game log how many rounds the bot needed to reach 3 VM, using the engine's event stream, so data exists when a target is chosen. |
| Decision method | Each turn is one action token. The bot picks its action from a **fixed priority list with some randomness**, so it doesn't play identically each game. The randomness uses the same **seeded** source as the dice, so any game is exactly replayable. |
| Attack trigger | Dislodge a blockader, plus opportunistic attacks when sharing a sector with a player ship and a simple strength comparison favours it. The strength comparison is the one piece of tactical evaluation the v1 bot needs, and it was later decided to be a **seeded Monte Carlo run of the real combat engine** (section 11), not a simple formula, so it is a significant piece of engineering. |
| Counterplay | The race to 3 VM is **not a pure race**. Counterplay is designed in: blockading the Central Nexus (Interact is blocked by opposing ships), destroying the bot's ships, and denying shared missions. The bot needs responses to each. |
| Being attacked | The bot is a full combatant: it fires back, makes damage choices and can retreat. |
| Shared enemy fights | **Free-for-all per V5.** In a sector with an enemy card, the player and bot are both engaged and can target each other. Spoils of War applies. |
| Exploration | The bot gets full discovery bonuses and enemy loot. Explored tiles are revealed publicly. |
| Missions | Real conditions, no timer shortcuts. |
| Mission deck | PvP missions (Asset Seizure x2, Privateer x4, Sabotage) are **removed for everyone**. |
| Presentation | Each bot action is shown, one at a time. |

- ~~"Never initiates combat" but "fights in shared sectors" is an arbitrary line.~~ **Stale: that rule was dropped** (see "Starting fights" above); the bot may initiate combat.
- With PvP missions removed, there is little reason to attack the bot outside shared enemy fights.

## 3. Combat rules (V5 is authoritative)

- All ships and tokens in a sector are engaged in **one combat** that is free-for-all, not two "sides": who may target whom is the `isOpposing` relation (`CMB-5`). Fleets have up to 3 ships. One initiative list across all combatants, **recomputed at the start of every combat round from each combatant's live speed and then fixed for that combat round** (`CMB-3`). **Combatants with equal speed form an initiative group and fire simultaneously** (everyone in the group rolls before any of the group's damage is resolved, so tied combatants can destroy each other; see `CMB-1`). Full V5 multi-ship combat is in scope. A combat runs to completion inside the action (or Maintenance step) that started it (`CMB-4`).
- **Damage events:** group all hits from one combatant's attack against one target. The owner chooses **once**: take cubes (1 per hit, hull upgrade slots first) **or** discard one component (**the defender chooses which, `LOT-3`**) to negate the whole event. **No mixing.**
- **Overflow (house ruling):** a ship cannot choose cubes unless **every** hit in the event fits in its free slots. Otherwise it must discard a component. Enemies cannot discard components, so overflow destroys them.
- **Destruction:** only when a ship must resolve a hit with no free slots and no components left.
- **Spoils of War:** at most once per combat round, per damaged defending ship, per attacking player, and only when the defender chose cubes. Not per cube. **The defender chooses which unprotected cargo resource is taken** (`LOT-2`). Never applies to Beam Projector shots (no combat round).
- **VM (changed from V5):** redeeming a mission puts 1 VM in the **faction resource pool**, not in a cargo hold. It is therefore never lost to damage or destruction, and cannot be taken by Spoils of War or any other means. VM is **never spendable**: it is not a payable resource, cannot be traded, and does not count as "any resource."
- **Win condition (revised):** **the game ends immediately when a player takes their third VM** (4 or 5 in longer games), not at the end of a round. Redeeming a mission is an action, so only one seat can take a VM at a time and **there can be no ties**. "Across your fleet" no longer applies. *(This replaces the earlier "3 VM in the pool at the end of a round".)*
- **Mission cap:** a player may hold at most 3 missions in total (4 or 5 in longer games), counting completed ones. Completed missions cannot be discarded. Uncompleted missions can be discarded when taking new ones. The cap therefore equals the VM target, so winning means completing every slot.
- **Retreat:** declared at the start of a combat round (sequentially in first-player order, `CMB-6`), resolved after damage using the evasion contest (d6 + speed per opposing combatant, one hit per failed contest, no Spoils). The destination is one adjacent sector across a full gate connection, chosen when the retreat executes (`CMB-6`).

### Interaction between decisions
- Single-choice events plus forced component discard on overflow make large salvos strongly component-destroying. This affects balance for every multi-die weapon and for Phase Lattice.

### Combat interactivity
The player makes every combat decision (retreat declaration, weapon targeting, damage choice, retreat attempt). Bot fights resolve automatically through the same decision points.

## 3a. Starting ship (Nomad-class Corvette)

The V5 rulebook text does not list the Corvette's stats (they are on the ship card). The owner stated:

| Stat | Value | Simulator |
|---|---|---|
| Cargo | 2 | 2 |
| Crew slots | 1 | 1 |
| Hull | 1 | 1 |
| Weapon | 1 energy weapon, 1 die, hits on 5+ | same |
| Speed | **2** | **1** (differs) |
| Upgrade slots | **4** | 4 |

**Early fragility is intended.** A bare Corvette (hull 1, no components) is destroyed by its second hit, **or by any single damage event of 2 or more hits** (the overflow rule below: cubes are only allowed if every hit fits, and there is no component to discard). Players are meant to upgrade quickly and avoid fights early. The bot is subject to the same fragility, which means a bot that attacks too early can lose its only ship.

Consequences of speed 2: the player acts first against every speed-1 enemy (Iron Enforcer, Iron Goliath, Brood Reaper, Hive Mother) and ties with speed-2 enemies (Iron Skiff, Prism Star-Fortress). Warp Drive Mk I takes the ship to speed 3, tying the Swarm Larva and the Prism Templar.

## 4. Enemies (decided per card)

| Enemy | Decision | Source |
|---|---|---|
| Iron Enforcer | 2 weapons, 2 dice each, 4+ | V5 |
| Iron Goliath | 2 weapons, **4 dice each**, 5+ | V5 |
| Prism Spark | Player **energy weapons get -1 to hit** against it, plus +1 damage from kinetic and missile hits that scored at least 1 hit | V5 |
| Prism Star-Fortress | Phase Lattice caps hits **per weapon, per round** at 2 | Simulator |

Note: Spark's -1 to hit and Templar's -1 damage are different mechanisms. The engine must distinguish "modifies the attacker's roll" from "modifies the hits that land". **Granularity (`CMB-9`):** the Prism "+1 damage from mass/missile/drone that scored at least 1 hit" and Templar's "-1 damage from energy" apply **once per damage event** (all of one attacker's weapons against that enemy in one combat round), not once per weapon.

Other enemies are unchanged between sources (Iron Skiff, Prism Templar, Prism Star-Fortress's Absorber, the whole Hive faction), checked line by line against the simulator's `enemyShips.ts`. The Prism Spark in the simulator uses "Prismatic Refraction" instead of V5's "Prismatic Resistance", already ruled above. **Underworld Extortion** is ruled below and changes "cargo" to the pool.

### Iron Syndicate: Underworld Extortion (V5 ruled)
When an Iron Syndicate ship is destroyed (Skiff 1, Enforcer 2, Goliath 3), the **player who dealt the destroying damage event** (including Beam Projector kills and Self-destruct explosions) pays that many resources **from their Faction Resource Pool** (not cargo). The **paying player chooses** which (never VM) and they **return to the general supply**. If the pool has fewer, they **lose what they have** and the rest is waived. This is a cost of killing Syndicate ships and interacts with the Spoils and pool rules (the pool can be drained by this but not by Spoils).

## 5. Content and effects

- **Card data is the source of truth.** Cards are rendered from structured data. Artwork is only the picture.
- **Effects:** a complete effect language, designed in full before building, then implemented only for the first content slice.
- Roughly 55 components. About half are plain stats or simple modifiers. 25 to 30 are one-offs, many acting at unusual moments (out-of-turn reactions, on-destruction triggers, cross-sector attacks, rule rewrites).

### Mitigation for the risk of an unvalidated language
When designing the language, walk the hardest cards through it **on paper** even though they are not in the first release:
- Interceptor Drone Rig (out-of-turn reaction attack)
- Mercenary Uplink (rewrites who counts as an opponent)
- Temporal Echo (rerolls already-rolled dice)
- Self-destruct Protocol (triggers on destruction, rolls against other ships)
- Beam Projector (attacks an adjacent sector)

## 6. Technical direction (no implementation yet)

- **Persistence:** cloud saves with sign-in. The stated reason is a possible stepping stone to human multiplayer.
- **Engine location:** runs in the browser for v1, **written to be portable to a server** later. It must not depend on the screen, the clock or anything outside the game state.
- **Event stream:** the engine should produce a sequence of discrete events (moves, rolls, draws) rather than only final states. This serves animation, the combat log, replay and any future AI.
- **Save versioning (decided, `SAV-1`):** saves are **full snapshots with schema migrations**. A big rules change may mark old saves "legacy". Old engine versions are not kept ("finish under starting rules" was rejected).
- **Save integrity (decided, `SAV-2`):** the game is saved immediately after any step that reveals hidden information or uses randomness ("commit points"), in addition to turn boundaries, so reloading cannot be used to scout or to replay a roll differently.

### Challenged, partly open
- Cloud accounts and server state for hypothetical multiplayer is speculative. Local autosave plus export would be cheaper. The owner chose cloud anyway.

### Weapons and unique technologies (settled)

**The simulator implements only part of the component list.** Its engine has logic for plain stats and dice, Apocalypse's double hits, Pneumatic Ram-Loader, Drone Hangar, Cloaked Slip Drive, the accuracy items and the defences. Most weapon passives and unique technologies exist only as card text with no behaviour behind them (Gauss, Rapid-Fire Railgun, Compressor Gun, Concussion Missiles, Torpedo cargo effect, Nanite Swarm, Interceptor Drone Rig, Thermal Pyre speed penalty, Beam Projector, Void-Core Overdrive, Auto-Loader Turrets, Temporal Echo, Self-destruct, Stealth Field, Scavenger Drones, Nano Repair Bots, Impulse Thrusters). The simulator is also missing Mercenary Uplink. For these, the rulebook wording is the starting point and each is a new ruling.

| Component | Ruling |
|---|---|
| Heavy Gauss Accelerator | If this weapon scores **exactly 1 hit** (judged per weapon, not per event), that hit is resolved as **its own separate damage event**, and the defender **cannot discard a component** for it: it must take a damage cube. If the target has no free hull slot, the ship is **destroyed**. The attacker's other hits remain a normal damage event. This is a deliberate exception to "one damage event per attacker per target." **"Exactly 1 hit" is judged on the weapon's final hit count after weapon-level steps** (to-hit, rerolls, Repulsor, Phase Lattice cap, hit weights) **and before event-level steps** (Prism +1/-1, Shield Specialist), see `CMB-9`. |
| Rapid-Fire Railgun | 5 dice, 4+. Additional **-1 to hit for each point of the target's current speed** (including temporary effects such as Impulse Thrusters and the Thermal Pyre penalty). A natural 6 still hits (the general dice rule). Effective only against slow targets. |
| Speed changes mid-round | **Superseded by `CMB-3`.** Each combat round's initiative is computed at the start of that combat round from every combatant's **live speed (permanent and temporary adjustments)** and is then fixed for that combat round, even if speeds change during it. A change (for example Thermal Pyre) therefore affects the **next** combat round's initiative. Speed used by Railgun, Evade and Retreat contests is the live speed at the moment they resolve. Temporary effects still expire as their own wording says (usually end of globalRound; Impulse Thrusters when Maintenance begins). |
| Impulse Thrusters | Spend **1 H3 from the pool** on the owner's **action turn** to add +1 speed to the ship. Once per **global round**. The boost **ends when Maintenance begins**, so it helps Move range, Evade rolls, Railgun penalties and the initiative of Attack-initiated combat during the Action phase (`CMB-3`), but **not** Maintenance enemy combat. |
| Pneumatic Ram-Loader | 1/2 slot, up to 2 copies. Mass weapons gain +1 die and +1 to hit. If **any** mass attack die is a natural 1, the owner takes **1 damage once per attack action** (not per die). The simulator charged 1 per natural 1. |
| Concussive Compressor Gun | 4 dice, 5+. If it rolls **1 or more natural 1s**, the owner takes **1 damage once per firing of this weapon**. Each natural 6 hits for 2 damage. |
| Self-damage (general) | Counts as a damage event for the owner (cubes or component discard, owner's choice). Does not grant Spoils of War to anyone. |
| Torpedo Bay (simulator: Cluster Torpedo Battery) | 2 dice, 5+. On each hit, the attacker may spend **1 H3 from the faction pool** to make the target remove 1 resource from its cargo hold. **The target chooses which resource.** It returns to the general supply, and the attacker gains nothing. No effect on enemies (they have no cargo). Works even if the defender chose a component discard. |
| Nanite Swarm Drones | 2 dice, 5+. May exhaust ready action tokens for **+1 to hit per token**. Eligible tokens: the **general tokens** (Trade, Interact, Tactical) and **tokens belonging to this ship** (its Move token and any officer tokens on it). **The tokens are exhausted before the roll, as one of the attacker's pre-roll commitments (`CMB-8`)**, not after seeing the dice. Gives **no bonus in Maintenance combat**, because everyone has passed and all tokens are exhausted. That is its trade-off. |
| Interceptor Drone Rig | Reaction: when attacked by a Mass Accelerator, Missile or Drone weapon, may make a 1 die, 5+ attack with this weapon. A reaction is **free**: it doesn't use the weapon's normal shot, and firing normally doesn't prevent reacting. Target is the attacker. **It cannot react to a range attack** (a Beam Projector shot from an adjacent hex): Decoy Launcher and the other defences still apply to such a shot, but no Interceptor reaction is offered (`CMB-10`). | Thermal Pyre Cannon | 2 dice, 4+. Any ship **damaged** by it has Speed -1 for the remainder of the round. This is a temporary speed change that lasts until the end of the globalRound. | Beam Projector | 1 die, 4+. Tactical attack action against an **opposing ship in an adjacent sector tile**, either a rival (player/bot) ship or an enemy faction ship. ### Enemy kills and reward cards (changes from V5)
- **V5 "Anomaly Interactions (Collect)" is removed.** There is no Interact action to buy reward cards on a hex.
- **When a player destroys an enemy ship, they receive its reward cards** (the asset cards under the enemy card, which are component cards) **directly**, and take the enemy ship card (used by some missions).
- **When several fleets fight the same enemy, the fleet whose damage event destroys the LAST enemy ship or token in the hex takes the reward cards** (the PDF's "once all enemy ships and tokens are destroyed"); the **enemy card itself goes to whoever destroyed that card** (`LOT-4`). Swarm Larva tokens are not ships for kill cards or kill triggers.
- **Range kills (Beam Projector):** the shooter takes the **enemy ship card** but not the reward cards. The reward cards stay on the hex and go to the **next player to enter it**.
- **Reward cards install for free.** The taker may install any of them **immediately**, but **only on a ship in that hex** with room (`DCK-4`; the usual Fit rule applies, so an installed component may be voluntarily discarded to make room, which is not "lost in combat"), or **set one or more aside** and install them later during **any future upgrade Interact action at no cost**. **There is no limit** on how many set-aside cards a player holds. Set-aside cards are **hidden** to rivals (information rules apply to the bot too).
- **Claiming left-behind rewards:** the next player to **end a move in the hex** takes them. **Passing through does not count.** Unclaimed cards **stay on the hex until claimed** (no end-of-round discard). If someone **explores the hex with an Interact action without entering it**, the new reward cards are **added to the cards already there**. **Confirmed (`RWD-1`): leftover cards accumulate with the new reward cards, and whoever kills the new enemy, or next ends a move there, takes the whole stack, leftovers included.**
- A ranged kill's **enemy ship card goes to the shooter** (needed for the faction missions), as ruled under Beam Projector.
- "Explores the hex without entering it" only happens via the Comms Specialist exploring an adjacent Anomaly; new cards are added to any already there.

### Dice rules (settled)
- A **natural 6 always hits** and a **natural 1 always misses**, regardless of modifiers.
- Consequences: weapons that hit on 6+ ignore all to-hit penalties. To-hit penalties have a floor of 1 in 6, so stacking defences has diminishing returns.

### Consequences to remember
- Thermal Sinks can negate any Prism enemy weapon (all have 2 dice or fewer) for 1 H3. It is close to a hard counter to the faction. **Softened by the 3-for-1 exchange** (see "Trade and markets"): any pool cost can be paid with 3 other resources, so "needs a specific resource in the pool" is only a price, not a hard requirement.
- Resource-cost reactions are **interrupts**: the engine must pause during the attacker's turn and ask the defender before dice are rolled. With the "step through every decision" choice, one attack can prompt several times.
- The cost resource and location matter: pool resources cannot be stolen by Spoils of War, but cargo can.

### Corrections to earlier statements
- Slot costs: only the Inertial Dampener differs from the simulator (and the accuracy items match). Earlier text that said "several" defences differ was wrong.

### Game end (ruled)
- The game ends **immediately** when a player takes their third VM (the Redeem action). No ties are possible. The **Blockade** mission is checked at the end of Maintenance, so a game-ending redeem can simply come first, and the mission is not reached. The UI shows every seat's VM and completed missions as public information, and **no extra warning** is given when the bot is one redeem from winning. **No rules limit on game length (`GEN-1`):** there is no round limit and no draw. Simulations and tournaments abort at 200 global rounds and record the game as "stalled"; in play the human may Abandon a game (recorded as abandoned).

### Passing and the Action phase (ruled)
- Players alternate **one action at a time**, starting with the first player. A player may **pass at any time**, which flips all their remaining tokens to exhausted and takes 1 resource from the Central Nexus. **Passing is final for the round**: a passed player is **skipped** until Maintenance resets tokens. The remaining players keep taking turns (one player may end up acting alone) until **everyone has passed**. A player must pass when all their tokens are exhausted.
- Board size by seat count (V5): **2 seats** 10 planet tiles and 6 anomaly tiles, **3 seats** 15 and 9, **4 seats** 20 and 12. **Board layouts, start positions, tile orientation and gate connectivity are ruled in section 13.**

### Maintenance phase: enemy ship tokens (ruled)
- **"Enemy ship tokens" are only spawned tokens**, such as the Hive's Swarm Larva. The Maintenance step "if no damage was repaired in a sector containing enemy ship tokens, remove one ship token" therefore **clears leftover larva** from sectors where no repair happened. Normal enemy cards are not tokens and are never removed by that step.
- **Maintenance order (V5):** Enemy Combat, Enemy Ship Repair (1 cube from every damaged enemy, then the token rule), Enemy Escalation (shuffle one random reinforcement card into the enemy deck), Market Shift, Nexus Replenishment, Recruitment, New Objectives, Reset Counters, New Ship (for a player with no ships), Pass the First Player token. *Rulings that touch it: Nano Repair Bots at the start of Maintenance, Data Siphon at the end of the Action phase, Impulse Thrusters end when Maintenance begins, Blockade checks at the end of Maintenance.*

### Enemy decks (ruled)
- **Card versus token (clarified):** the Hive's Swarm Larva exists both as a Tier-1 enemy **card** (it can be drawn, fought and kept as a defeated card) and as a spawned **token** (Brood Hatchery, Endless Swarm). They share stats but are different objects: only tokens are removed by the Enemy Ship Repair token rule, and only cards count for Hive Cleansing. Tokens are never "ships" for kill triggers (`LOT-4`).
- **The "kill an enemy: shuffle two Level 2/3 cards into the enemy deck" rule is removed (an old rule).** Only the Maintenance Escalation step adds reinforcements: one random card per round from the reinforcement deck.
- **When the reinforcement deck is empty, Escalation adds nothing.**
- **When the enemy deck is empty, the Explore Interact action can no longer be used.** An undiscovered Anomaly tile entered by Move still **flips and gives its discovery bonus** (and movement still ends), but there is **no enemy and no reward cards**. The loss of the reward-card source for the rest of the game is **intended** late-game pressure: upgrades then come only from the Outer Rim markets.
- The starting enemy deck is the V5 deck for every seat count (it does not scale with seats). Per-level, per-faction card counts are in `content-data.md` (placeholders until the owner supplies the real numbers).

### Movement and Evade (V5 read, rulings marked)
- **Move:** one ship moves up to its Speed in hexes along warp gate connections (gates must match on both sides, apart from Warp Engineer, Cloaked Slip Drive and Graviton Warp Conduit which allow half-connected; **see section 13, `MAP-5` to `MAP-7`, for what "connected", "half-connected" and orienting a newly revealed tile mean**). **Ruled: Move can only be used if the ship starts in a sector with no opposing ships (rival ships included).** Otherwise it must use Evade. Movement **ends on flipping a new undiscovered hex**, and Reference Card 1 says it ends on entering a hex containing another ship. A ship with 0 Speed cannot Move but can still Evade. **Ruled: movement ends immediately on entering any hex that contains an opposing ship (rival or enemy)**, so a ship can pin another by entering its hex, and the entering ship must then Evade or Attack to act (Move is blocked for it too). This matches Mercenary Uplink's "movement is not blocked" wording, where a friendly ship is not an opposing ship. **Enemy faction ships never sit in planetary sectors, only in Anomaly sectors, and they never move.**
- **Entering a new Anomaly hex:** immediate discovery bonus (2 different printed resources) and draw an enemy card, with 1, 2 or 3 face-down asset cards placed under it according to the enemy's level. Reward asset cards come only from the markets matching the discovery bonus resource types: **each reward card is drawn face-down from the top of the deck of one of the tile's two discovery-bonus markets, and the player whose action drew the enemy card chooses the market for each card** (`DCK-3`).
- **Evade (tactical action, uses a token):** moves the ship **1 adjacent sector regardless of Speed**, and **must follow warp gate connections** (ruled: gates required on both sides, Cloaked Slip Drive allows half-connected). Roll **once per opposing ship in the sector**: d6 + your Speed vs d6 + their Speed, equal or higher = no effect, lower = 1 failed evasion (1 hit); total all failed contests into **one damage event**. The ship completes the move unless destroyed. **The destination can be any legal adjacent sector, including one with enemy ships** (combat there happens in Maintenance) **and an undiscovered tile** (it is flipped and oriented under `MAP-6` or `MAP-7`, and the discovery bonus and enemy card apply as for Move). Evade is not a combat Retreat.
- **Restrictions by opposing ships (ruled):** **Interact, Repair and Move** cannot be used by a ship in a hex with **opposing ships** (rivals or enemies). **Trade is never blocked** (no ships block Trade: enemy factions are never in planetary sectors, and rivals do not block it). This overrides Reference Card 1's wording on Trade.
- **Consequence:** two rival fleets in one hex **lock each other out of Interact, Repair and Move** (a mutual trap): the only ways out are **Evade** (a contested roll that can cost hits), **Attack**, or the other fleet leaving. Trade still works if it is a planet. **A standoff is a legitimate state** and Maintenance does not force a fight.
- **Bot when locked out:** it **uses the strength check**: attack if it expects to win, otherwise **Evade** (Move is also blocked while pinned, so Evade is the only exit). It never just waits. *Note: this makes pinning a real threat. A bot's Evade can fail and cost hits, and Evade needs a Tactical token (the same token the exploration rule keeps ready).*

### Upgrades at the Outer Rim Nexus (V5 read, rulings marked)
- There are **four asset markets**, numbered 1 to 4 and tied to an asset type and resource: **Sector 1** Weapons / Offensive Tech (PC), **Sector 2** Propulsion / Utility (H3), **Sector 3** Cargo / Life Support (QP), **Sector 4** Hull / Defensive (TC). Each has a deck and **3 face-up market cards**. **The markets sit on the Outer Rim Nexus tiles, and with fewer than 4 seats a Nexus tile holds two markets** (`MAP-4`). A ship at a Nexus may buy from any market on that tile. *(This replaces the earlier wording "each Outer Rim Nexus is numbered 1 to 4".)*
- **Nexus Hop (Interact option at any Outer Rim Nexus, `NEX-1`):** a ship may travel to another Outer Rim Nexus without a Move action. See section 15.
- An **Upgrade Interact** buys **one** asset card **for a ship in that sector**, either by paying the **printed cost of one of the 3 face-up cards**, or by **paying 3 of the sector's resource to draw a random card from its deck**. (The 3-for-1 exchange applies.)
- **Deck draw (ruled):** you receive the random card (for the ship), then you **discard one of the 3 face-up cards (your choice) and refill from the deck**, so the market stays at 3 and rotates. **The flat 3-resource price replaces the printed cost**, so it is the cheap-but-random option.
- Common technologies are always available during an upgrade action by paying the printed cost.
- **Market refill (`DCK-1`):** whenever a face-up card is bought (by printed cost), that market is **immediately refilled to 3** from its deck. Deck-draw purchases refill as ruled above. There is no asset refill step in Maintenance.
- **Empty decks (`DCK-2`):** when an asset deck (or the crew deck) is empty and a draw or refill needs a card, its **discard pile is reshuffled into a new deck**; if the discard pile is empty too, nothing is drawn (a deck-draw purchase from an empty deck is unavailable, and a reward card must come from the tile's other market, or is not placed if both are empty). The enemy deck is different: it does **not** reshuffle (ruled under "Enemy decks").
- **Fit (ruled):** the card goes on a ship with a free upgrade slot. If it doesn't fit, the owner may **discard an installed component from that ship to make room** (voluntary, part of the same action, so Salvage Expert does **not** pay). Otherwise the card cannot be taken.
- **Set-aside reward cards:** installed free during an upgrade Interact, **any number in one action** as long as ships have room. **The ship must be at an Outer Rim Nexus** (it is an upgrade Interact, so it is blocked if opposing ships are in the hex).
- **Random draw that doesn't fit (ruled):** if the buyer cannot or will not make room, the card is **discarded and the resources are lost**. That is the gamble.
- **Bot buying:** the bot **scores the 3 face-up cards** with a simple value function (weapon dice, defences, hull, cargo, plus mission nudges) against price and takes the best affordable one. It uses a **random draw only when no face-up card is worth its price**. *The value function needs authoring per component; unlisted exotic components default to a low score so the bot mostly ignores them unless told otherwise.*

### Building new ships (ruled)
- **Only the Nomad-class Corvette exists as a buildable ship.** A fleet is **up to 3 ships**, and variety comes from upgrades. Other classes are not in scope.
- **A new Corvette costs 10 resources in total.** **Mix (ruled, adjustable): 3 H3, 3 TC, 2 QP, 2 PC.** Missing types can be paid with the 3-for-1 exchange. *Resource names: Titanium Carbide (TC), Helium-3 (H3), Plasma Cells (PC), Quantum Processors (QP).* Built with an Interact action at an Outer Rim Nexus (blocked by opposing ships). The starting ship is free.
- *Pace check for later: with cargo 2 a bare Corvette moves about 2 resources into the pool per delivery cycle, so a second ship is a mid-game purchase (and the Armada mission is correspondingly hard early).*

### Crew (V5 read, rulings marked)
- **Recruitment cost (ruled): Ensigns cost 3 resources and Commanders cost 5 resources in total.** The Appendix's per-card costs (Pilot 4 H3, Tactical 4 PC, Scout 2 QP + 2 PC, Merchant 2 QP + 2 H3, and the Commanders at 6 to 9 resources) are **out of date. The user will update them so each totals 3 (Ensigns) or 5 (Commanders).** **Supplied so far (the four plain Ensigns, each totals 3):** **Pilot 3 H3** (Move token), **Merchant 1 H3 + 2 QP** (Trade token), **Tactical 3 PC** (Tactical token), **Scout 1 PC + 2 QP** (Interact token). *Pending: the costs of the other Ensigns (Long-range Sensor Specialist, Piloting Ace, Warp Engineer) and all Commanders (5 each). Do not build those costs from the V5 appendix.*
- **Crew is how a fleet gains more actions (ruled, `ACT-1`).** Each crew member comes with **one action token of a fixed type** (a Pilot gives a Move token, a Tactical a Tactical token, a Scout an Interact token, a Merchant a Trade token, and so on), and that token can be used **only by the ship the crew member is attached to**. The Corvette alone has the base four tokens (a Move token on the ship, and the fleet-wide general Trade, Interact and Tactical tokens); everything beyond that comes from crew. Officer tokens exhaust and ready like other tokens (Maintenance reset, Officer Training Command, Pass).
- **Luxury Quarters:** reduces the recruit cost of any crew member **for that ship** by **any 2 resources of the buyer's choice** (minimum 0).
- **Recruitment:** an Interact action at **any Nexus** (Central or Outer Rim) buys one of the 4 face-up crew cards into a ship with free crew capacity, and the owner **may remove another crew member to make capacity**. Officer action tokens work only on their own ship. In Maintenance the oldest (leftmost) crew card is discarded and the market refills to 4 (an empty crew deck reshuffles its discard pile, `DCK-2`).

### Trade and markets (V5 read, with one interpretation)
- **Harvest:** a ship takes **any number** of resources matching the planet's supply type into its cargo, **up to cargo capacity**, **for free**. It then places **2 damage cubes** on the supply area, and cannot harvest while any cube is there. **The number on the card is a cap per action** (one harvest takes at most that many of that type).
- **Fulfil demand:** the ship moves **any number** of matching resources from its cargo to the **Faction Resource Pool**, up to the demand number per type (a cap per action), then places **2 damage cubes** on the demand area. Blocked while any cube is there.
- **Both in one action:** one Trade action can harvest and fulfil demand together. **Trade is never blocked by ships** (ruled under "Restrictions by opposing ships" above: enemy factions never sit in planetary sectors and rivals do not block Trade; this overrides the V5 wording that enemy ships block it).
- **Market Shift (Maintenance):** removes **1 cube** from every supply and demand area on each planetary sector, so a used area is **locked for 2 Maintenance steps** (usable again in the round after next).
- **The pool** is the only spendable store (upgrades, crew, new ships). **Cargo cannot be spent until delivered.** Purchases may **exchange 3 resource cubes for 1 resource of any type**.
- **3-for-1 exchange (ruled):** it can be used **any number of times** for any cost paid from the pool: for each missing resource, spend 3 other pool resources of any types (never VM). It applies to **purchases and also to ability costs** (Decoy Launcher's TC, Torpedo Bay's H3, Impulse Thrusters' H3, Cloaked Slip Drive's QP, Mercenary Uplink, Gravitic Anchor, and so on). *Consequence: the "needs a specific resource" counters (e.g. Thermal Sinks needing H3 in the pool) are softer than earlier notes assumed, since 3 other resources can stand in. The interrupt UI must offer the exchange when the exact resource is missing.*
- **Passing (ruled):** a player who passes takes **1 resource of their choice from what remains** of the Central Nexus supply, **wherever their ships are** (no blockade or location effect). The Nexus resets to 1 of each type during Maintenance. Ruled as **"it can never be empty"**: each seat passes once per round and there are at most 4 seats against 4 resources, so a passer always gets something, but **later passers may not find their preferred type**, which makes passing order matter. **The game must cap at 4 seats (1 human plus up to 3 bots)** for this to hold, which already matches the product decision.
- *Consequences to remember:* cargo capacity is the throttle on income (a bare Corvette has cargo 2); both areas of a planet are shared between the human and every bot, so planets are contested; pool income otherwise comes only from Pass (1 resource from the Central Nexus, which resets to 1 of each type each Maintenance), discovery bonuses and card effects.

## 8. Information and recovery (settled)

- **Bot information:** the bot decides using **public information only**, exactly what a human player would know, and the engine enforces this. The engine must therefore produce a **per-player view** of the game state (what each player may see). Hidden information includes face-down tiles (planets as well as Anomalies), the asset cards under enemy cards, set-aside reward cards and shuffled decks. **Cargo and faction pool contents are public** (`INF-1`), so bots may use rivals' cargo and pool in their decisions. **There are no secret missions**: all missions are public (V5's "secret mission" wording is stale). This is the same boundary human multiplayer would need later.
- **Last Ship Recovery (changed, `REC-1`):** a basic ship appears at the next Maintenance (the New Ship step) on **any Outer Rim Nexus tile the player chooses, even if opposing ships are there**; if it is occupied by opposing ships the new ship **arrives pinned** (Move blocked; it must Evade or Attack). This removes the V5 lockout when no free Nexus exists. **What persists (assumed, to confirm):** everything that belongs to the player and not to a ship (pool, VM and completed missions, held uncompleted missions, set-aside reward cards, general action tokens); everything bound to a lost ship (components, crew and their tokens, cargo, ship-specific mission progress such as Galactic Tour and Blockade) is lost.

## 9. Watch during play (no decision needed now)

1. **Balance consequences of the VM change:** nobody can take or destroy a rival's VM, so the only way to stop a leader is to win first or blockade the Central Nexus. Fighting the bot has little strategic purpose beyond blockades and shared enemy fights.
2. **Nexus lockout:** can a bot hold the Central Nexus indefinitely, and what dislodges it? (Attack, per the bot attack rules.)
3. **Recovery onto an occupied Nexus (`REC-1`):** a recovered ship may now arrive pinned on an occupied Outer Rim Nexus. Watch for abuse (a rival camping a Nexus to pin a player's recoveries) and for the 2-seat board, which has only two Outer Rim Nexus tiles (`MAP-1`).
4. **Cargo versus pool in the interface:** the rules already say cargo can't be spent until moved to the pool, and the specific costs are settled. Only how the interface shows the two stores remains.
5. **Crew and action tokens for the bot:** a lone Corvette has 4 tokens (Move, Trade, Interact, Tactical), and every extra action comes from crew whose officer tokens work only on their own ship (`ACT-1`). How the bot spends them (and how it values recruiting) is a build detail.
6. **Blockade-breaking tools:** Security Credentials (Central Nexus only), Mercenary Uplink (flagged "Overpowered?" in V5, kept as ruled) and Comms Specialist (any adjacent Anomaly or Nexus hex, no restrictions) all bypass the "cannot Interact with opposing ships present" rule. Together they may make blockades, which the bot design relies on as counterplay, too weak.
7. **Range kills and rewards:** Beam Projector kills leave reward cards on the hex for the next player to enter. Could produce odd bot behaviour (racing to the hex) and unclear hand/slot limits.
8. **Tactical-initiated traits:** Drone Hangar, Shield Specialist and Bounty Hunter only work when the owner starts combat. A player-heavy-defence build gets no benefit from them, and enemies attack in Maintenance, so these will rarely trigger in solo play.
9. **Beam Projector plus Bounty Hunter:** the Beam Projector shot is one-sided, and Bounty Hunter pays on its hits, so a ship with both can farm resources from rivals with no retaliation. Watch in play and playtest the Beam Projector's price. (`CMB-10` also means an Interceptor Rig cannot react to a Beam Projector shot, which strengthens this combination.)
10. **Start Nexus disconnected from the Central Nexus (`CON-1`, resolved by the Nexus Hop `NEX-1`; residual risk only):** Monte Carlo runs (4000 games per setting, the whole board explored, `analysis/gate-graph-sim.js`) show that a given start Nexus has no full-gate route to the Central Nexus in about 3% (2 seats) to 6% (4 seats) of cases with careful orientation, and about 18% to 25% with random orientation; at least one seat is cut off in 6% (2 seats) to 19% (4 seats) of careful games. Because any ship at an Outer Rim Nexus can hop to another Outer Rim Nexus, a seat is only stranded if **no** start Nexus reaches the Central Nexus, which is about 0.05% to 0.1% of careful games and about 5.5% to 6.3% of random-orientation games. The residual random-orientation case is watched, not ruled. See `technical-proposal.md` section 9.4.
11. **Interact-token bottleneck (and the crew-less slice):** the fleet has one general Interact token per globalRound, and Commission, Upgrade, Build, Recruit, Redeem and the Nexus Hop (`NEX-1`) all need an Interact. **Crew is how a fleet gets more actions (`ACT-1`):** a Scout adds an Interact token, a Merchant a Trade token, and so on, but only for the ship the crew member sits on. A rough lower bound of 5 Interact actions to win (2 Commissions, 3 Redeems) is only the floor; the realistic count is much higher. **The first content slice has only the four plain Ensigns (`content-data.md`), so extra actions are limited to one Move, Trade, Tactical or Interact token per crew member, and Commanders' traits are absent.** The economy-only simulation (P1 first task) must be run both without crew and with the four-Ensign set to see how much pace depends on crew.
12. **Small sector decks in the first slice:** the slice's market 2 (Propulsion) holds only two card types, so deck-draw purchases and rewards from H3 tiles repeat quickly (`content-data.md`). With `DCK-2` the discard pile reshuffles, so the same cards cycle.

### Bot trading
- **Route scoring:** the bot evaluates **short routes** (harvest at a reachable planet, deliver to a matching demand) and picks the best by **pool gain per action and travel cost**, with seeded randomness breaking ties. It does **not** plan by need: purchases are handled separately by the priority list, using the 3-for-1 exchange for missing types.
- **Contested planets:** the bot **checks the cube lock before committing to a move** and will not head to a locked planet unless the lock will clear by the time it arrives (Market Shift removes 1 cube per Maintenance).
- **Tunable:** route length horizon (how many moves ahead), tie-break randomness.
- **Passing:** the bot passes when it has **no useful action left** (every remaining action scores below a floor), **or earlier** if the Central Nexus holds a resource type it badly needs **for a planned purchase** and a rival is likely to take it first. *Consequence: the bot needs a notion of a "next planned purchase" (a target component, crew or ship) even though trade routing is not need-driven. That target comes from the priority list and the mission nudges.*
- **Enemy ships on its route:** the bot **fights an enemy if the strength check passes** (enemies are targets for combat missions and rewards), and **otherwise avoids** that hex when routing.
- **Exploring (ruled, replaces "no safety check"):** the bot **explores using Move actions only while its Tactical token is still ready**, so that if the revealed enemy fails the strength check it can **Evade** away on its next turn. It does not explore with the Tactical token exhausted. Evade can fail (each failed contest is a hit), so this reduces but does not remove the risk of losing the ship. A discovered enemy that passes the strength check is fought.
- **First player:** random in round 1 (seeded), then the token passes around the seats each Maintenance as in V5.

## 11. Bot and missions (settled; tunables remain)

- **Approach: incidental completion.** The bot follows its general priority list (trade, explore, upgrade, fight, with seeded randomness). Missions complete when their conditions happen to be met, with nudges for two mission groups (see below). **No per-mission planners.** Accepted cost: pace is unpredictable.
- **Taking a mission:** when a slot is free, the bot scores the visible missions by **how close its current fleet already is to the condition** and takes the best one, with seeded randomness among ties.
- **Scoring:** each mission type has a **fixed base difficulty rating** (set once, tunable), **adjusted by a simple state check where one exists** (e.g. Armada scores higher if the bot already has 2 ships). Event missions ("after taking this mission") use the base rating only.
- **Discard rule (completed missions can never be discarded, and "after taking this mission" progress is lost on discard):** the bot may discard an uncompleted mission only if it has had **no new progress for N global rounds**, counted from when it was taken or from its last progress (N tuned later). Then, if a visible mission scores clearly better than it, it swaps. This prevents churn and still lets a stalled mission go. Accepted: the bot may hold a mission it will almost never complete for N rounds. (The engine tracks mission progress for every player, human or bot.)
- **Nudges:** only the two largest mission groups get explicit nudges while the bot holds a mission of that group: **Build/state** missions (All Aboard, Full Roster, Balanced Design, Armada, Standardisation, Master Engineer, Resource Tycoon, Cargo Kingpin: 8 cards) bias upgrades, recruiting and ship purchases toward the condition, and **Combat** missions (Devastation, Sector Pacification x3, Ironclad Survivor, Syndicate Bust, Prismatic Salvage, Hive Cleansing: 8 cards) bias which enemies to hunt. **Trade (4 cards), Exploration (5), Shield Calibration / Evasive Master / Industrial Titan (3) and Blockade (1) get no nudges**: they complete incidentally or not at all, which is an accepted consequence. Deck composition after removing the PvP missions is 29 cards of 26 types. **The first content slice uses a filtered 27-card deck (`MSN-3`)** that drops only Prismatic Salvage and Hive Cleansing (the slice has only Iron Syndicate enemies); All Aboard and Full Roster stay, because the four plain Ensigns are in the slice. That makes the Build/state nudge group 8 cards and the Combat group 6 cards. **Humans may discard uncompleted missions freely (`MSN-2`);** the bot keeps the N-round discard rule above as its own policy.
- **Mission rulings (apply to humans and bots):**
  - **Blockade:** the **same ship** must be in the Central Nexus tile at the **start of the Action phase** and at the **end of Maintenance** (after the Reset step), and **cannot leave and return** in between. It must survive Maintenance combat there. The mission must be **taken before that round starts**.
  - **Devastation:** **2 or more hits delivered to one ship in a single damage event**, on **any ship (enemy or rival)**. It does not matter whether the defender takes it as cubes or components. "Hits" are counted **after defences and bonuses** (e.g. the Prism +1 counts). Beam Projector shots count (a one-shot damage event).
  - **Sector Pacification (x3):** a **cumulative total of 2 damage** across any Level 2/3 enemy ships (may be split between ships, events and rounds) after taking the mission. Damage is counted as in Devastation (after defences and bonuses).
  - **Ironclad Survivor:** a combat counts as won when it **ends with all opposing ships destroyed or retreated** (the player retreating does not count as a win), and **at that moment** one of the player's ships in the combat has **2 or more damage cubes** on its hull.
  - **Evasive Master:** counts **active tactical Evade actions started from a sector containing an opposing ship**, where **at least one evade roll was made and every roll passed** (so no damage). Retreats in combat do not count, and neither do automatic successes with no roll. Two such actions after taking the mission. The two **need not be consecutive**.
  - **Shield Calibration:** any **installed defensive component** that results in **fewer hits than there would have been without it** counts: Energy Shields, Thermal Sinks, Decoy Launcher, Reactive Plating, Magnetic Repulsor Grid rerolls that turn a hit into a miss, and **to-hit penalties** (Magnetic Shields, Inertial Dampener, Pulse Defense Grid) **if the penalty actually turned at least one die from hit to miss**. **Crew traits (Shield Specialist) do not count.** A defence that triggers but changes nothing does not count. *Engine note: this means defence effects must report "hits prevented" to the mission tracker.*
  - **Syndicate Bust / Prismatic Salvage / Hive Cleansing:** state check at redeem time. **Any** defeated enemy card of that faction in the player's play area counts, **including ones taken before the mission was taken**. On redeeming, the **2 cards used are discarded** (they cannot count toward another mission). **Whoever deals the destroying damage event takes the card**, including **Beam Projector** kills and **Self-destruct** explosions.
  - **Galactic Tour:** the **same ship** visits **2 + player count** different Anomaly tiles after taking the mission. **Player count = all seats, bots included.** **Passing through a tile counts as entering it** (per the card). **If the ship is destroyed, progress is lost.** Note this differs from claiming range-kill rewards, where passing through does **not** count.
  - **Stellar Cartographer:** enter 3 different Anomaly tiles in a **single global round** (Action phase plus Maintenance), **passing through counts**, and the tiles may be split across the player's ships.
  - **Warp Pioneer:** 2 or more Move actions with the **same ship in a single global round**, **by any means** (a second Move token, a flipped Move token, tile effects, Void Scout, and so on).
  - **Industrial Titan:** **5 or more resources spent on ship components across the whole global round**, counted as the **actual amount paid** after reductions (Quartermaster), with free reward-card installs counting as 0.
  - **Perimeter Lockdown:** 2 Interact actions on **different Outer Rim Nexus tiles within one global round** (the same or different ships), after taking the mission.
  - **Anomaly Resonance:** the unique Activate effect used on 2 different Anomaly sectors after taking the mission. **Using an adjacent hex's effect remotely through Comms Specialist counts.**
  - **Trade Negotiator:** on each of **3 different planets** (**4** in games with **3 or more seats, bots included**), deliver **at least 2 demand in a single Trade action**, after taking the mission.
  - **Market Saturation:** in one Trade action, take the planet's **printed maximum supply** or satisfy its **printed maximum demand** (all of one type). A market already depleted by earlier trades **cannot** satisfy it, even if everything left is taken. *Watch: this can make the mission hard or impossible on a worn market.*
  - **Tri-System Supply Run (x2):** deliver demand to **2 different planet tiles within one global round**; **each planet tile counts as a system**.
  - **Balanced Design:** a ship with **3 different component categories** installed (weapon, defence, cargo, hull, crew, drive/utility). The printed base hull and weapon do not count.
  - **Master Engineer:** a ship with **4 or more installed components** (the printed hull and base weapon do not count), duplicates included.
  - **Standardisation:** the **same named component** installed on two different ships.
  - **All Aboard, Full Roster, Armada, Resource Tycoon, Cargo Kingpin:** **as written in V5** (state checks at redeem time). **Cargo Kingpin counts cargo only** (the pool does not count, and VM can no longer sit in cargo). Resource Tycoon counts the pool's four resource types, and VM is not one of them.
  - **Where missions are taken and redeemed:** missions are **taken at the Outer Rim Nexus locations** and **redeemed at the Central Nexus**, where the player gets the VM into the pool. **This matches V5**: a ship at an Outer Rim Nexus takes 1 mission from the face-up market (4 cards) with an Interact action (the Interact token, and normal opposing-ship restrictions apply); the market refills to 4 during Maintenance ("New Objectives"). A Central Nexus blockade therefore blocks **redeeming** but not **taking** missions.
  - **Starting missions:** each player (and bot) starts with **2 public missions** and can redeem only **one**: **redeeming one discards the other** (the only case where a held mission is discarded other than by the uncompleted-mission discard rule). **Both count toward the 3-mission cap**, so a player starts with 1 free slot. **There are no secret missions** (V5's "secret mission" wording is stale). The bot's choice between its two starting missions is made by the same scoring rule, just by completing whichever it can first.
- **Redeeming:** once a held mission is complete, **redeeming is the bot's top priority**. It heads for the Central Nexus and redeems as soon as possible.
- **Blockaded Nexus:** if a rival holds the Central Nexus, the bot **attacks if it is at least as strong** (using the simple strength comparison from section 2). If it is **not** strong enough, it **works toward getting stronger** (a strength-building mode that changes its priorities, e.g. upgrades and weapons).
- **Strength measure: seeded Monte Carlo.** The bot runs the **real combat engine** a number of times on the current public state and attacks if its win rate is **above a threshold** (number of runs and threshold to be tuned). Consequences: the engine must be **fast, side-effect free and runnable on a copy of the state**; simulations must use a **separate derived seed** so they never disturb the game's RNG sequence; the simulation uses **public information only** (installed components are public, set-aside reward cards are not); and the opponent's decisions inside the simulation (damage choice, reactions) need a **fixed default policy**, because the human's choices are unknown.
- **"Getting stronger":** when blockaded and too weak, **upgrading and weapon/defence purchases move to the top of the bot's priority list** until it passes the strength check, then it attacks.

| `MAP-7` | **Moves that allow half connections** (Warp Engineer, Cloaked Slip Drive on Evade, Graviton Warp Conduit). At least one of the two tiles must have a gate on the edge crossed. **If the tile being left has a gate on that edge, the new tile may be oriented any way, gate or not.** **If it has no gate there, the new tile must be oriented so a gate faces it.** A normal move from a tile with no gate on the edge is not legal. |
| `MAP-8` | **"Adjacent" means touching.** Comms Specialist, Beam Projector and Long-range Sensor Specialist use adjacency only and **do not need a gate** between the hexes. Hexes can be adjacent without being connected: **adjacent and connected are two different concepts** (owner-confirmed). |
| `MAP-9` | **Tiles are revealed only by a ship entering them** (Move, Evade or a Graviton Warp Conduit move). Comms Specialist uses an Interact on an **already revealed** adjacent tile and **cannot reveal a new one**. |

## 14. Rulings from the technical review

| ID | Ruling |
|---|---|
| `CMB-1` | **Tied initiative.** Combatants with equal speed form an initiative group and **fire simultaneously**: all of them roll and fire before any of the group's damage is resolved, so tied combatants can destroy each other, and a ship destroyed by a group-mate's damage still fires. Groups act in descending speed order, with initiative fixed at the start of each combat round (`CMB-3`). |
| `CMB-2` | **Decoy Launcher timing.** Used after the attacker rolls, once the defender sees the result, before damage. |
| `ORD-1` | **Order of simultaneous effects.** When several effects trigger together (damage events from a tied group, Self-destruct chains, end-of-Action-phase effects such as Data Siphon and the Helium Nebula toll, reactions in the same window), the **first-player token holder's effects resolve first, then clockwise by seat**. Within one seat, **the owner chooses the order of their own simultaneous effects** (`CMB-10`; a prompt appears only when 2 or more are available and could interact). **Install order, then component ID, is the default order used by bots and by simulation, and the deterministic tie-break when an order does not matter to the owner.** A component moved by Scrap Reclamation Yard takes a fresh install sequence number. A card may state a different order. |
| `RWD-1` | **Reward stack on a hex.** Reward cards left on a hex (for example after a Beam Projector kill) stay until claimed. New reward cards (from a Comms Specialist explore, or a new enemy) are **added to the stack**. **Whoever kills the enemy there, or next ends a move in the hex, takes the whole stack, leftovers included.** |
| `MSN-1` | **Anomaly Resonance.** Counts only Interact tiles' Activate effects (tiles 1, 2, 3, 5, 8, 9, 14, 16 to 22). Passive tiles do not count. Remote use through Comms Specialist counts. (Tile 4 is removed, `TIL-1`.) |
| `TIL-1` | **Tile 4, Overclocking Relay, is removed from the game for now.** The Anomaly pool is 21 tiles (numbered 1 to 22 without 4; numbers are not reassigned). The setup draw of 6, 9 or 12 Anomalies comes from these 21. |
| `INF-1` | **Cargo and faction pool contents are public information** to all seats. |
| `ECO-1` | **The general supply is unlimited.** |
| `SAV-1` | **Save policy.** Snapshots with schema migrations; major rules changes may mark old saves "legacy". Old engine versions are not kept. |
| `UX-1` | **Undo.** The human may undo back to the start of the current turn. Bot turns are not undoable. |
| `UX-2` | **Undo lock.** Undo is locked for the rest of the turn as soon as anything hidden is revealed (tile flip, card draw, peek) or any dice are rolled. |
| `UX-3` | **No auto-decline.** The human is asked whenever a reaction is available. The engine still does not prompt for a reaction that cannot be used (component not installed, or cost unaffordable even with the 3-for-1 exchange). |

## 15. Rulings from the second review: terms, combat model, loot, decks, saves, soft-locks, attack pipeline

Source: the second technical review and the owner's answers to it. IDs are stable. Where a row conflicts with an older ruling or a section 7 row, **this section wins**. Rows marked *(assumed)* are my own choices where the owner gave no answer; **veto any of them**. `CON-1` (start-Nexus connectivity) is resolved by `NEX-1`; the open items are listed in section 12.

| ID | Ruling |
|---|---|
| `TRM-1` | **Terms.** A **globalRound** is one Action phase plus one Maintenance phase; "round" in card text means a globalRound unless the card says "combat round". A **combatRound** is one full pass of every combatant through the initiative order inside one combat. A **turn** is one seat's single non-free action choice plus any free actions it takes while it holds the turn. The code uses these three names and nothing else (no bare "round"). |
| `CMB-3` | **Initiative.** At the start of **every combat round**, each combatant's initiative speed is computed from its **live speed, including all permanent and temporary adjustments** (Profit-Chaser, Thermal Pyre, Impulse Thrusters and the like). That value is **fixed for the rest of that combat round** even if speed changes mid-round; the change takes effect in the next combat round's initiative. Solar Flare's +1 applies only to Evade/Retreat contests (not initiative). Railgun and the Evade/Retreat contests read live speed at the moment they resolve. Tokens spawned during a combat round (Brood Hatchery, Endless Swarm) first act in the **next** combat round. Ties form simultaneous groups (`CMB-1`). This reverses the earlier "initiative fixed at round start, temporaries ignored" ruling. |
| `CMB-4` | **Combat length.** Combat is resolved **inside the action or Maintenance step that started it**, as a loop of combat rounds, and ends when **no mutually targetable pair** of combatants remains in the hex (everyone on one side destroyed or gone, or only allies left). Retreat and Evade remove combatants from the loop. There is no round cap in the rules. The engine has a **safety guard at 100 combat rounds** that ends the combat with a `CombatStalemate` event; the simulator and tests treat that event as a bug signal, not a normal outcome. |
| `CMB-5` | **Free-for-all.** Combat in a hex includes **every ship and token in it**, regardless of who started it. Two combatants are **opposing** when their owners differ (a human, each bot rival and each enemy faction are all different owners; a faction's own ships and tokens never oppose each other), **except** pairs made friendly by Mercenary Uplink. A combatant may target only ships that oppose it. Each shot resolves against one chosen target, and a ship destroyed mid-round is removed immediately (it still fires if simultaneous, `CMB-1`). Who an enemy ship picks as its target when several oppose it is **open** (section 12). |
| `CMB-6` | **Retreat.** Retreat is declared **sequentially in first-player order** (the token holder first, then clockwise), and later declarers **see** earlier declarations. A ship may declare a retreat only if it has a **legal destination: one adjacent hex across a full gate connection** (`MAP-5`; half-connections do not count, Slip Drive does not apply). The destination may be an undiscovered hex (it is flipped and oriented by the retreater under `MAP-6`; discovery bonus and enemy card are drawn as for a normal entry) or a hex holding enemies. The destination is **chosen at execution**, not at declaration. A Magnetic Grapple cancel keeps the ship in the combat; Dense Asteroid auto-succeeds as before. Retreat resolves at the point in the combat round the earlier rulings set. |
| `CMB-7` | **Maintenance combat.** At the start of the Enemy Combat step the engine **snapshots** the list of sectors holding both enemies and ships, and their participants. Sectors resolve one after another in **seat order of the ships in them** (token holder's ships first, then clockwise), ties broken by hex coordinate. A ship that retreats during Maintenance is not part of any other sector's combat that Maintenance. **Spawned tokens persist:** they stay in the sector where they spawned, **across globalRounds**, until removed, and the only removal mechanism is the existing Enemy Ship Repair step (see "Maintenance phase: enemy ship tokens"). While they remain they are enemy combatants like any other: they count when the snapshot decides which sectors hold both enemies and ships (so a sector with only tokens and a player ship still fights in Maintenance), they fight whenever a combat occurs in their hex, and they are part of the "last enemy ship or token" test for rewards (`LOT-4`). A token spawned during a combat first acts in the next combatRound (`CMB-3`); one spawned during Maintenance combat is not in that Maintenance's snapshot, so it first fights in a later combat. |
| `CMB-8` | **Attack pipeline, part 1: commitments and dice.** The attacker declares **targets and every pre-roll commitment together** (drone launch, Void-Core Overdrive, Nanite Swarm token exhaustion), then defenders in **ORD-1 seat order** may use pre-roll reactions (Thermal Sinks). **Dice count** = printed dice plus additive bonuses (Ram-Loader and the like), **then ×2 for Overdrive**, **then** defender reductions (Reactive Plating -1 per copy, Thermal Sinks -2), minimum 0. |
| `CMB-9` | **Attack pipeline, part 2: weapon-level versus event-level.** Per weapon, in this order: roll, to-hit (including Prism Spark's -1 against energy), rerolls and caps (Phase Lattice caps **per physical weapon**), Gauss's "exactly 1 hit" test on the weapon's own final hit count, hit weights. Then, once per **damage event** (all of one attacker's weapons against one target in one combat round): Prism Templar -1 and Prism +1, then the Shield Specialist bonus **last**. Shield Calibration credit accrues **sequentially** (each earlier event counts toward the next). |
| `CMB-10` | **Reactions and ordering.** The **owner picks the order of their own simultaneous effects** (this refines `ORD-1`: ORD-1 still orders **seats**, and install order is only the default for bots, simulation and tie-breaks). An **Interceptor Rig cannot react to a range attack** (a Beam Projector shot from an adjacent hex); Decoy Launcher and passive defences still apply to it. Temporal Echo and similar "all those dice" wording refers to all dice the owner rolled in that one action. |
| `CMB-11` | **Self-damage and sequencing.** Self-inflicted damage (Overdrive, Self-destruct) is **queued with the group's damage events** and resolves with them under `CMB-1`, not before. **Torpedo Bay resolves before Spoils of War.** |
| `LOT-1` | **Cargo on destruction.** When a ship is destroyed, **the attacker takes all its cargo into its faction pool, but only if the attacker's ship is in the same hex** (this includes Smuggler's Hold contents). In every other case the cargo goes back to the **general supply**: a Beam Projector kill from an adjacent hex (the special case), a kill by an enemy faction, self-damage and the Helium Nebula toll. With several same-hex killers, the one whose damage event dealt the destroying damage takes it *(assumed)*. |
| `LOT-2` | **Spoils of War choice.** The **defender chooses** which unprotected cargo resource is taken. It never applies to Beam Projector shots. |
| `LOT-3` | **Component loss.** When damage destroys a component, **the defender chooses which** (Expert Marksman's attacker-chooses wording is the exception). |
| `LOT-4` | **Tokens and kill credit.** Swarm Larva **tokens are not ships**: they do not trigger kill-based effects (Scavenger Drones and the like). Enemy-card rewards go to whoever destroys the **last enemy ship or token in the hex**, and the **enemy card goes to whoever destroyed that card**. |
| `LOT-5` | **Cargo, crew and hull models** *(assumed)*. Cargo is a **simple count of units per resource per ship**, capped by that ship's capacity; losing capacity (a cargo component destroyed) discards cargo above the new cap, **the owner choosing which** (to supply). Crew on a destroyed ship are lost with it, and their cards go to the crew discard. Hull is a **count of intact hull cubes**, not a set of individually identifiable cubes. |
| `DCK-1` | **Market refill.** A face-up market is refilled to 3 **immediately** when a card is bought from it. |
| `DCK-2` | **Empty decks.** An empty asset or crew deck **reshuffles its discard pile** when a card is needed. If the discard is empty too, nothing is drawn. The enemy deck never reshuffles. |
| `DCK-3` | **Reward card source.** Reward cards are drawn **face-down from the top of one of the two asset decks matching the tile's discovery-bonus resources** (market 1 = PC, market 2 = H3, market 3 = QP, market 4 = TC), and the **player whose action drew the enemy card picks the market for each card**. If the chosen deck is empty (after any reshuffle) the other is used; if both are empty no card is placed. |
| `DCK-4` | **Reward installation (also `RWD-2`).** A reward card may be installed on a ship **in that hex only**; otherwise it is set aside, hidden, and may be installed later at an upgrade at no cost. |
| `SLT-1` | **Slots.** Common technologies take **1 slot each**; any two half-slot items share a slot. Capacity is counted in halves (the Corvette has 4 slots = 8 halves). |
| `SAV-2` | **Commit points.** After any step that reveals hidden information (tile flip, card draw, peek) or uses randomness, the engine writes a **local snapshot immediately** (the resolution stack is serialisable, so this is possible mid-action) and queues or debounces the cloud write, in addition to turn-boundary saves. Snapshot migrations must handle in-flight stack frames. Undo (`UX-1`, `UX-2`) remains turn-local and is locked after these events. Reloading therefore cannot be used to scout or to reroll. |
| `REC-1` | **Last Ship Recovery.** The new ship appears on **any Outer Rim Nexus of the player's choice, even if occupied**, arriving **pinned** if opposing ships are there. Persistence of a player's non-ship assets is as in section 8 *(assumed, owner to confirm)*. |
| `MSN-2` | **Discarding missions.** On their own turn a player may **freely discard an uncompleted mission** (its progress is lost; completed missions can never be discarded; the starting-pair rule is unchanged). |
| `MSN-3` | **Slice mission deck.** 29 cards minus Prismatic Salvage and Hive Cleansing = **27 cards of 24 types** (the 7 PvP missions were already removed). All Aboard and Full Roster are kept because the slice includes the four plain Ensigns (Pilot, Merchant, Tactical, Scout), which cover all four crew types for Full Roster. *(Revised from 25 cards when crew entered the slice.)* |
| `GEN-1` | **No game-length limit in the rules.** Simulations and tournaments abort at **200 globalRounds** and record "stalled"; the human may Abandon a game. |
| `ENF-1` | **Determinism enforcement.** The ban on `Date.now`, `new Date`, `Math.random` and `localeCompare` in the engine is enforced by **ESLint** (`no-restricted-properties`, `no-restricted-globals`, plus an import boundary on the engine package). A TypeScript `lib` setting without DOM types is **not** enough on its own (these APIs are in the ES library) and is no longer claimed as enforcement. State is serialised by a canonical serialiser (sorted keys, no `undefined`) so hashes and replays are stable. |
| `NEX-1` | **Nexus Hop.** At any Outer Rim Nexus, **Nexus Hop is one of the Interact options** (alongside Commission, Upgrade, Build and Recruit). It **does not need a Move action or Move token**, and it **never links to or reaches the Central Nexus**: the destination is **another Outer Rim Nexus tile**. The cost is **1 resource**. It is an Interact, so the usual restrictions apply (it spends an Interact token, either the general one or an officer Interact token on the travelling ship, and it is blocked while opposing ships are in the hex). *(Assumed details, veto any: the cost is 1 resource of the owner's choice from the faction pool, never VM, returned to the general supply; the 3-for-1 exchange is irrelevant because any resource pays the cost, so a seat with an empty pool simply cannot Hop; the ship that uses the Interact is the one that travels; any other Outer Rim Nexus may be chosen, including an occupied one, and the ship then arrives as in `REC-1`, pinned if opposing ships are there; the destination needs no gate, no speed and is not stopped by enemy ships in between; it is not a Move for any card that says "Move".)* **Ruled by the owner: the Interact takes place on the exit hex only.** It does not count as an Interact on the destination hex (so it does not count there for Perimeter Lockdown), and it does not stop the player from taking a separate Interact on the destination hex later, if another Interact action is available. |
| `ACT-1` | **Crew gives actions.** Crew is how a fleet gains more actions. Each crew member brings one action token of a fixed type (Move, Trade, Interact or Tactical; for example Merchants give a Trade token and Scouts an Interact token), usable only on the ship the crew member is attached to. Moving crew between ships (Personnel Transporter) moves the token with them and keeps its ready or exhausted state. A lost ship loses its crew and their tokens. |
| `CON-1` | **RESOLVED by `NEX-1`: start-Nexus connectivity.** The gate-graph simulation (`technical-proposal.md` section 9.4) showed a start Nexus without a full-gate route to the Central Nexus in 3% to 25% of cases depending on orientation. With the Hop, a seat is stranded only if no start Nexus reaches the Central Nexus (measured: about 0.1% of careful-orientation games, about 6% of random-orientation games). So `MAP-6` and `MAP-7` stay as they are, and no other mitigation is needed. The 3% to 8% of hexes that are unreachable under normal moves stay unreachable, which is accepted. |
